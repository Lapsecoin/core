Key Differences
  • One address per node: Each running instance manages exactly one address. Cannot generate new addresses at will. Use separate node instances for separate exchange accounts.
  • Memo as deposit tag: Transactions carry a memo field. Use it to route deposits to exchange user accounts (like Bitcoin's label system, but in-transaction).
  • Integer ticks, not decimals: Amounts are in ticks (1 LAPSE = 10000 ticks). Avoid floating-point math; work in integers only.
  • Offline signing required: No RPC password authentication. Build, sign, and submit transactions from a separate offline process. Keep keys offline.
  • No nonce endpoint: Must count prior sent transactions to derive next nonce. See API docs for details.
Implementation Checklist
  • Run separate LapseCoin node for each exchange account
  • Store the node's address and keep the node online to receive deposits
  • Query /api/address/{addr}/balance periodically for deposit detection
  • Extract memo from received transactions to route deposits to users
  • For withdrawals:
    • Build transaction with outputs (recipients)
    • Sign offline with node's private key
    • POST signed tx to /api/tx/send
  • Use /api/fees for fee estimation (ticks per byte)
  • Track nonce by counting sent entries in address history
  • Call API from your server, not the browser (no CORS)
Cold Storage

For security:

  • Generate and sign transactions on an offline machine
  • Keep the node's private key offline, only load it for signing
  • Submit pre-signed transactions from a separate online service
  • Use /api/tx/send (no authentication required, just broadcast)
